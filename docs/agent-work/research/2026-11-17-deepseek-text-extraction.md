## Answer
DeepSeek is text-only for our purposes: use `deepseek-flash` (or `deepseek-v4-pro`) over OpenAI-style `/chat/completions` with SSE streaming. There is no native citations or PDF-in-chat feature, so we extract per-page text locally (poppler `pdftotext -layout`, split on form feed), cite via numbered sources and verbatim quotes, and verify quotes in code after NFC + whitespace normalization. For the client, plain `Net::HTTP` SSE (about 25 lines, zero dependencies) is the lowest gateway risk; `ruby-openai` is the shortest code that is documented against DeepSeek. Leave OCR out of v1, but add scanned-page detection so the app says "no text layer" instead of silently returning nothing.

## Key findings

### Q1 DeepSeek API today (docs read 2026-11-17)
- Formats: OpenAI base `https://api.deepseek.com`; Anthropic base `https://api.deepseek.com/anthropic`. Docs: "uses an API format compatible with OpenAI/Anthropic". Responses API also listed. — https://api-docs.deepseek.com/ ; https://api-docs.deepseek.com/quick_start/pricing
- Models: `deepseek-flash` (served by DeepSeek-V4.1-Flash-1017; recommended name) and `deepseek-v4-pro` (DeepSeek-V4-Pro-0813). Legacy `deepseek-v4-flash` and `deepseek-v4-flash-vision-exp` still accepted but route to V4.1-Flash. `deepseek-chat` (used in the ruby-openai README) is not in the current model table, so do not use it. — pricing page
- Both: context 1M tokens, max output 384K (393,216), thinking and non-thinking (thinking is the DEFAULT), JSON output yes, tool calls yes. `max_tokens` default 8K non-thinking, 64K thinking. — pricing page; https://api-docs.deepseek.com/api/create-chat-completion
- Streaming: `stream: true`, SSE, terminated by `data: [DONE]`; `stream_options: {include_usage: true}` requires `stream: true` else 400; usage arrives on the last content chunk. Thinking mode streams `delta.reasoning_content` before `delta.content`. — create-chat-completion; https://api-docs.deepseek.com/guides/thinking_mode
- Streaming keep-alive: server sends SSE comments `: keep-alive` while queued; "handle these empty lines or comments appropriately"; connection closed if inference has not started after 10 min. — https://api-docs.deepseek.com/quick_start/rate_limit
- Thinking switch (OpenAI format): body `{"thinking": {"type": "disabled"}}` (OpenAI SDKs pass via `extra_body`) or `reasoning_effort: "none"`. In thinking mode temperature/top_p-style params have no effect (no error). For RAG answers, disable thinking: faster first token, no `reasoning_content` to handle. — thinking_mode, create-chat-completion
- JSON mode: `response_format: {"type":"json_object"}` only; docs list only `text` and `json_object`, NO `json_schema`. Prompt must contain the word "json" plus an example; content may come back blank/spaces with `finish_reason: stop`, so check for blank and retry; set `max_tokens` high enough. — https://api-docs.deepseek.com/guides/json_mode
- Images: only `deepseek-flash` (vision); `deepseek-v4-pro` does not (Anthropic endpoint replaces images with `[Unsupported Image]`). Chat Completions images go as `image_url` parts (base64 data URL or http link; JPEG/PNG/GIF/WebP; 48 MiB request, 600 images). — https://api-docs.deepseek.com/guides/vision ; https://api-docs.deepseek.com/guides/anthropic_api
- PDF/file input: the chat-completions page lists no PDF/file input. The Anthropic-compat page says `document` blocks accept only `file` and `text` sources, citations are "Ignored", `search_result` "Not supported". So the old Claude design (document blocks, citations, search_result) does not carry over. Treat chat as text (and flash-only images). — anthropic_api page
- Separate DeepSeek OCR endpoint exists: `POST https://api.deepseek.com/v1/tools/ocr`, multipart `file` + `purpose` (`text_recognition` or `rich_layout_recognition`), PDF/DOC(X)/PPT(X)/images, 100 MiB, 1000 pages, 180 s total, $0.225 per 1000 pages; response `pages[{index (0-based), text, finish_reason}]`, text is raw model output and may contain `<｜ref｜>`/`<｜box｜>` tokens. Docs do not list languages or mention Vietnamese. A gateway may not proxy `/v1/tools/*`. — https://api-docs.deepseek.com/guides/ocr (Not used in the recommendation; the user asked for local extraction.)
- Gateway caveats (inference, nothing sourced about the user's gateway): model names may be aliased; `thinking`, `stream_options`, `reasoning_content` may be stripped or rejected; SSE may be buffered by a proxy; `/v1/` path prefix may differ; unknown fields may produce 400. Smoke test: one non-stream call, one stream call with `include_usage`, one with `thinking: disabled`.

### Q2 Ruby client options
| | `openai` (official) | `ruby-openai` | Net::HTTP (or Faraday) |
|---|---|---|---|
| Version | 0.125.0 (2026-11-16), Ruby >= 3.3, deps connection_pool, logger | 8.3.0 (2025-08-29, ~3 months old), Ruby >= 2.6, deps faraday, faraday-multipart, event_stream_parser | stdlib; faraday 2.15.1 if wanted |
| Base URL | `OpenAI::Client.new(base_url:, api_key:)`; default from `ENV["OPENAI_BASE_URL"]` | `OpenAI::Client.new(access_token:, uri_base:)` or `OpenAI.configure`; README has a DeepSeek example | you build the URL |
| Streaming | Chat: `client.chat.completions.stream_raw(...)` returns typed chunk objects (`create` raises ArgumentError if `stream` set). README documents only Responses streaming | `stream: proc { |chunk, _event| ... }`, each chunk parsed to a Hash; `chunk.dig("choices",0,"delta","content")` | `http.request(req) { |res| res.read_body { |buf| ... } }`, split on `\n\n`, drop lines starting with `:`, parse `data:` JSON, stop on `[DONE]` |
| Extra DeepSeek fields | `request_options: {extra_body: {thinking: {type: "disabled"}}}` (README documents `extra_body`) | pass any key in `parameters:` hash (passes through) | any |
| Risks | pre-1.0 (0.x) churn; typed models: whether unknown `reasoning_content` is reachable on delta objects NOT verified; gateway-unfriendly strictness unknown | URL builder appends `v1` to `uri_base` unless it already contains it (http.rb `uri`), so a gateway with another path needs `uri_base` containing `v1` or a path tweak; stale release cadence | you own parsing, error handling, retries |
- Sources: https://rubygems.org/api/v1/gems/openai.json, /ruby-openai.json, /faraday.json; https://github.com/openai/openai-ruby (README, lib/openai/client.rb, resources/chat/completions.rb, request_options.rb); https://github.com/alexrudall/ruby-openai (README, lib/openai/http.rb).
- Least code: `ruby-openai` (about 6 lines, documented DeepSeek, hash chunks). Least risk against an unknown gateway: Net::HTTP, because there is no URL rewriting, no typed-model validation, and every header/body field is visible. Inference: the loop is small enough that the dependency saves little.

### Q3 PDF per-page text
- poppler-utils in trixie: 25.03.0-5+deb13u4; amd64 208.5 kB download / 723 kB installed (+ libpoppler147, cairo, freetype, lcms2). — https://packages.debian.org/trixie/poppler-utils
- `pdftotext` options: `-layout` "Maintain (as best as possible) the original physical layout of the text" (default reorders to reading order); `-f/-l` first/last page; `-enc` default UTF-8; form feeds separate pages unless `-nopgbrk`; `-tsv`/`-bbox` give word bounding boxes; `-fixed` for tabular text; `-raw` "no longer recommended". The man page says nothing about Unicode normalization or ligatures. — https://manpages.debian.org/trixie/poppler-utils/pdftotext.1.en.html
- Per page: one call `pdftotext -layout in.pdf -` and split on `"\f"` (inference: use `split("\f", -1)` and drop the trailing empty element; page N = index N-1). One call is much cheaper than N calls with `-f N -l N`; page count from `pdfinfo` or the split. Use `-f/-l` only for retries of a single page.
- `pdf-reader` gem 2.16.0 (2026-08-09, Ruby >= 2.1; deps afm, Ascii85, hashery, ttfunk): `reader.pages.each { |p| p.text }`; converts to UTF-8; README says "Occasionally some text cannot be extracted properly... unrecognisable characters are output as a box", calls itself "primarily a low-level library", and says nothing about tables/layout or scanned PDFs. — https://github.com/yob/pdf-reader ; rubygems API. Pure Ruby saves an apt package (~1 MB) but has no documented layout preservation; Inference: poppler layout mode is the better table keeper, pdf-reader the simpler install.
- Tables: `-layout` keeps columns as runs of spaces (inference from the option's definition; not tested here). Feeding that to the LLM and chunking by page/blocks is adequate for a demo. If a table matters, `-tsv` gives word coordinates (more code). No other tool was researched (pdfplumber/mupdf not evaluated).
- Vietnamese: poppler decodes through the font's ToUnicode map and writes UTF-8. No doc says whether it emits precomposed or decomposed forms; search results indicate this is producer-dependent (Vietnamese stacked diacritics may be combining sequences) and that broken/missing ToUnicode yields wrong or box characters. `pdffonts` shows `uni` = yes when the PDF has a ToUnicode map, "a missing map doesn't necessarily mean the text can't be converted". Verdict: always `unicode_normalize(:nfc)` after extraction; test with 1-2 real Vietnamese PDFs, because legacy VNI/TCVN3 font hacks can only be seen on real files. — https://manpages.debian.org/trixie/poppler-utils/pdffonts.1.en.html ; https://en.wikipedia.org/wiki/Vietnamese_language_and_computers ; https://blog.loslab.com/en-us/delphi-pdf-library/pdflibpas-unicode-canonical-search-grapheme-clusters-delphi.html
- Detect no text layer (inference, no source defines a threshold): per page, after NFC and whitespace squeeze, count letters `text.scan(/\p{L}/).size`; if under about 20 (tune) mark `no_text_layer`. Also flag pages with many U+FFFD/box characters as "garbled". Optionally `pdfimages -list` shows a page that is one big image. Surface these pages to the user ("page N has no extractable text") rather than indexing empty chunks.

### Q4 OCR (optional)
- Debian trixie packages: `tesseract-ocr` 5.5.0-1+b1 (amd64 428.7 kB download / 2.3 MB installed; depends on libtesseract5, libleptonica6, libicu76, cairo, pango, curl, archive etc., plus `tesseract-ocr-eng` and `tesseract-ocr-osd`), `tesseract-ocr-vie` 1:4.1.0-2 (409.8 kB download / 534 kB installed, arch all). `pdftoppm` comes with poppler-utils: default 150 DPI, `-r` sets DPI, `-f/-l` pages, `-png`, `-gray`. — https://packages.debian.org/trixie/tesseract-ocr, /tesseract-ocr-vie, /poppler-utils ; https://manpages.debian.org/trixie/poppler-utils/pdftoppm.1.en.html
- Image size impact: the packages themselves are about 3 MB, the dependency libs (ICU etc.) are the bulk. My estimate: tens of MB (about 50-100 MB), NOT measured; measure with one `docker build`. Language data is tessdata_fast: the tessdata docs say "Most users will want tessdata_fast and that is what will be shipped as part of Linux distributions" (docs do not say explicitly that Debian ships fast; 534 kB for vie is consistent with that). — https://tesseract-ocr.github.io/tessdoc/Data-Files.html
- Usage: `pdftoppm -r 300 -f N -l N -gray -png in.pdf out` then `tesseract out-N.png stdout -l vie+eng`. Use 300 DPI for diacritics (my inference; default 150 is low for marks). Command shape is standard CLI, not freshly sourced.
- Quality: no direct benchmark found. A 2025 survey says Tesseract supports Vietnamese but "accuracy remains limited due to diacritic handling and document noise" (no numbers). An old how-to claims over 97 percent on one clean test image (old release, not reliable). Expect good on clean print, noticeable diacritic errors on scans/photos/tables, and no table structure. Pick `tessdata_best` only if you can accept a bigger download and slower runs (not in Debian packages). — https://arxiv.org/html/2506.05061v1 ; https://vietunicode.sourceforge.net/howto/tesseract-ocr.html
- Decision aid: leave OCR out if the corpus is born-digital (Word exports, text PDFs). Add it (about 5 extra apt lines plus a 15-line fallback branch) only if scanned PDFs are expected. Alternatives: DeepSeek OCR endpoint (above; Vietnamese support undocumented, gateway may not forward) or `deepseek-flash` vision on `pdftoppm` images (the vision page documents `image_url` base64; Vietnamese OCR quality not documented).

### Q5 Citations without native feature
- Established pattern (DeepSeek's own file-upload template): `[file name]: {file_name}\n[file content begin]\n{file_content}\n[file content end]\n{question}`. DeepSeek's web-search template numbers sources as `[webpage X begin]...[webpage X end]` and asks for `[citation:X]` markers at the sentence end, multiple like `[citation:3][citation:5]`, not collected at the end. This is a documented DeepSeek pattern (R1 README); the repo also says "Avoid adding a system prompt; all instructions should be contained within the user prompt" and temperature 0.6 for R1. That advice is R1-era; I found nothing for V4 either way, so put the rules in the user message or test both. — https://github.com/deepseek-ai/DeepSeek-R1 (README, "Usage Recommendations")
- Nothing DeepSeek-specific found on refusing when context lacks the answer. Design it explicitly (inference): define a fixed refusal string, e.g. `NOT_FOUND`, and make the model return JSON `{"answer": "...", "citations":[{"source": 2, "quote": "..."}]}` or `{"answer": "NOT_FOUND", "citations": []}`. JSON mode is supported (`json_object`, include the word "json" and an example, retry on blank), but streaming JSON is awkward. Options below.
- Chunk header suggestion for the prompt: `[S1] file=report.pdf page=7` then chunk text, `[/S1]`. Instruct: "Cite as [S#] after each claim; for each citation give a verbatim quote copied exactly from that source; if sources do not contain the answer, reply exactly NOT_FOUND."
- Verification in code (inference, standard Ruby): for each (source, quote), check the quote is a substring of the retrieved chunk after normalizing both with: `unicode_normalize(:nfc)` (Ruby String method; default form is NFC per general Ruby knowledge, the ruby-doc page I fetched was truncated before the method section), replace all `\p{Space}` runs (including NBSP U+00A0, `\f`, newlines, and layout-mode runs of spaces) with a single space, strip, and optionally `downcase` (Vietnamese letters are cased; `String#downcase` is Unicode-aware in Ruby >= 2.4). Also normalize curly quotes and hyphen/dash variants, and strip soft hyphens U+00AD; join end-of-line hyphenation only if you see it in real files. Do not use NFKC (it rewrites ligatures and some symbols and can make a quote match text that was not there; fine for lookup, keep it off for display). Failing quotes: drop the citation, and if no citation passes, show "not found" (or retry once). Because `-layout` inserts many spaces, whitespace collapse is mandatory; because page text may have NFD marks, NFC on both sides is mandatory.
- Display the quote from the chunk (map back via the matched offset in the normalized text, or show the whole retrieved sentence), not the model's text, so what the user sees is guaranteed verbatim.

## Options / tradeoffs
| Option | Pros | Cons | When to pick |
|---|---|---|---|
| Net::HTTP SSE | zero deps, full control of path/headers/body, easy to handle `: keep-alive` and `reasoning_content` | about 25 lines to own and test | Default behind an unknown gateway |
| `ruby-openai` 8.3.0 | shortest, DeepSeek example in README, Hash chunks | adds `/v1` to `uri_base`, 3-month-old release, 3 deps | Gateway is vanilla `.../v1/chat/completions` |
| `openai` 0.125.0 | official, active, typed | 0.x churn, typed deltas vs `reasoning_content` unverified, `stream_raw` for chat is undocumented in README | If already standardising on it |
| Plain-text answer with `[S#]` + quotes, verified after stream | streams token by token, simple | quotes parsed from text (regex) | Default for UI streaming |
| JSON mode answer+quotes | easy to verify | not streamable as text, blank-output quirk | Non-streaming path or second pass |
| pdftotext -layout | table columns kept as spaces, fast, one call | NFD possible, one more apt package, no OCR | Default |
| pdf-reader | pure Ruby, per-page | no documented layout, no tables | If you refuse any apt dependency |
| Tesseract vie | tiny language pack, local | diacritic errors, extra libs, no tables | Only if scans expected |

## Recommendation
- Model: `deepseek-flash` with `thinking: {type: "disabled"}`, `stream: true`, `stream_options: {include_usage: true}`, no `response_format` for the streamed answer. Keep `deepseek-v4-pro` as a config switch (it cannot read images).
- Client: Net::HTTP with a small SSE loop (ignore lines starting with `:`, handle `[DONE]`), base URL and key from env. Reason: no URL rewriting or typed-model surprises behind a gateway.
- PDF: `pdftotext -layout` once per file, split on `\f`, NFC + whitespace-normalize, flag pages with fewer than about 20 letters as `no_text_layer`. docx: LibreOffice to PDF as in the earlier brief, then the same path.
- OCR: out of v1. Revisit with `tesseract-ocr tesseract-ocr-vie` + `pdftoppm -r 300` if a real scan appears.
- Citations: `[S#]` numbered source blocks with file+page header, verbatim quote required, `NOT_FOUND` sentinel, quote verified as a normalized substring of the retrieved chunk; drop unverified citations; no verified citation means "not found" in the UI.
